① El problema (decisiones de diseño)

"Hoy, si una marca quiere mostrar sus productos en 3D o realidad aumentada, necesita desarrollar una app nativa o algo a medida — es caro y lento. Y aunque lo logre, no tiene una forma simple de publicar ese modelo y compartirlo con sus clientes, ni de medir si la gente realmente lo usa. Ese es el problema que detectamos."

② La solución — modelAR

"modelAR es una plataforma web multi-tenant. El cliente entra, elige un modelo 3D de un catálogo —que combina la API de Sketchfab con modelos que nosotros curamos— y arma una campaña. La plataforma le genera automáticamente un visor de realidad aumentada con un código QR: el usuario final escanea el QR desde el celular y ve el producto en AR directamente en el navegador, sin instalar ninguna app. Y todo lo que pasa ahí —vistas, activaciones de AR, clicks en el botón— se mide con analíticas. Multi-tenant significa que cada cliente y cada organización tienen sus datos completamente aislados."

Sectores reales soportados: ecommerceturismoeducacioninmobiliariomuseo

"Por debajo son tres servicios desacoplados que se comunican por HTTP/JSON. El frontend, modelar-web, en React. Un gateway, modelar-api, que es la puerta de entrada. Y modelar-core, en NestJS, que tiene toda la lógica de negocio y es el único que habla con la base de datos, que es PostgreSQL en Neon. Además, core consume la API externa de Sketchfab para los modelos 3D. Algo importante: el navegador nunca habla directo con core ni con la base — siempre pasa por el gateway."

④ La decisión de fondo

"La decisión central de la arquitectura fue separar en tres servicios con responsabilidades bien distintas: presentación en el front, borde y seguridad en el gateway, y lógica más datos en core. Cada uno se desarrolla, despliega y escala por separado. El detalle de por qué separamos el gateway de core lo explica [nombre] en su parte."

⑤ El despliegue

"Para el despliegue usamos la plataforma que mejor encaja con cada pieza: el frontend en Vercel, ideal para apps de React; api y core en Render; y la base de datos en Neon, un Postgres serverless."
