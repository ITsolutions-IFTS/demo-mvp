Guión hablado — 2 · modelar-web · Panel admin Integrante 2 · 5 min · React 19 + Vite · gestión de campañas

El frontend que usan los clientes para crear y administrar sus campañas.

① El stack (arquitectura)

"El front está hecho con React 19 y Vite, todo en TypeScript. Para el ruteo usamos react-router en modo HashRouter. Y para el estado global no usamos Redux ni librerías externas: usamos el Context API de React. Tenemos cuatro contextos principales —autenticación, organizaciones, campañas y colecciones— más dos de UI, para los toasts y los diálogos de confirmación. Cada contexto encapsula su estado y las llamadas a la API de su recurso."

En App.tsx los providers se anidan: Auth → Organizations → Campaigns → Collections, envueltos por Toast y Confirm.

② Pantallas / módulos (módulos)

"El panel tiene varias pantallas, que son las rutas bajo /admin: el login, organizaciones, el listado de campañas, el formulario para crear o editar una campaña, la pantalla que genera el QR de cada campaña, las colecciones, y un dashboard de métricas. Todas las rutas del admin están protegidas: si no hay sesión, el componente ProtectedRoute te manda al login." 
// rutas del admin (App.tsx)
/admin/login   /admin/organizaciones   /admin/campanas
/admin/campanas/nueva   /admin/campanas/:id/qr
/admin/colecciones   /admin/metricas   /admin/dashboard

③ Cómo consume la API (decisiones / código)

"Toda la comunicación con el backend pasa por una sola capa, services/api.ts. Ahí hay una función apiFetch que envuelve el fetch nativo y centraliza tres cosas. Primero, agrega el token JWT en el header Authorization como Bearer, leyéndolo de sessionStorage. Segundo, le pone un timeout de 10 segundos con AbortController, así una request colgada no deja la UI esperando para siempre. Y tercero, maneja los errores de forma uniforme: si el backend devuelve un 401 y nosotros habíamos mandado un token, interpretamos que la sesión expiró, limpiamos el token y disparamos un evento global; el contexto de auth escucha ese evento y desloguea automáticamente. El login guarda el access token y el refresh token, y al recargar la página rehidrata la sesión llamando a /auth/me." 
if (res.status === 401 && token) {
  clearToken(); clearRefreshToken();
  window.dispatchEvent(new Event(UNAUTHORIZED_EVENT)); // → auto-logout
  throw new Error('Sesión expirada...');
}

④ Decisiones de diseño

"Las decisiones del front: usar Context API en vez de Redux, porque para el alcance era más simple y suficiente. Guardar el token en sessionStorage en vez de localStorage, así la sesión se cierra al cerrar la pestaña, que es un poco más seguro. Rutas protegidas con ProtectedRoute. Y soporte multi-tenant: el usuario opera sobre su organización."

⑤ Pruebas (pruebas)

"Para testing usamos vitest con Testing Library. Tenemos tests del cliente de API, de las utilidades de storage, y de las funciones que calculan estadísticas de campañas. Son tests unitarios que corren sobre jsdom, sin navegador real."

⑥ Fragmento representativo (código)

"Un fragmento representativo es cómo el contexto de campañas crea una y actualiza el estado: llama a la API y, cuando vuelve la campaña creada, la agrega al principio de la lista en memoria, así la UI se actualiza al instante sin tener que volver a pedir todo." 
const addCampaign = async (data) => {
  const created = await apiCreateCampaign(data);
  setCampaigns(prev => [created, ...prev]); // aparece al instante
  return created;
};
