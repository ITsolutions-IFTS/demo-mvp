Slide 4 · P2 (Matías)

Arquitectura: 3 capas desacopladas

Separamos el sistema en tres capas que se comunican por HTTP.

🖥️ WEB · React

La experiencia del usuario. SPA optimizada con Vite.

🛡️ GATEWAY · Express

El escudo: lo único expuesto a internet (Helmet, CORS).

🧠 CORE · NestJS

El cerebro: toda la lógica + PostgreSQL · Redis.

El core nunca toca internet directamente → más seguro y escalable.
IMAGEN: diagrama (no captura) — WEB → GATEWAY → CORE → PostgreSQL · Redis.
P2 (Matías):
“Por dentro, lo separamos en tres capas. La web es lo que ve el usuario. El gateway es un escudo: es lo único expuesto a internet, filtra y asegura cada pedido con Helmet y CORS. Y el core, hecho en NestJS, es el cerebro: ahí vive toda la lógica y la base de datos. La clave: el core nunca toca internet directamente — eso lo hace más seguro y nos deja escalar cada capa por separado.”

Slide 5 · P2 (Matías)

El núcleo: una decisión clave

Decisión → aislar las reglas de negocio del resto (Clean Architecture). El resultado:

🔁 Intercambiable

Cambiamos la fuente de datos sin tocar una sola regla de negocio.

🧪 Testeable

Probamos la lógica sin levantar una base de datos.

✔️ Confiable

Rollback atómico probado (Jest + Vitest): nunca quedan datos a medias.

IMAGEN: sin captura (conceptual). Opcional: ícono de “círculos concéntricos” (Domain → Application → Infrastructure).
P2 (Matías):
“Dentro del core tomamos una decisión clave: aislar las reglas de negocio del resto, con arquitectura limpia. ¿Qué ganamos? Dos cosas concretas: podemos cambiar de dónde vienen los datos sin tocar una sola regla de negocio, y podemos testear esa lógica sin levantar una base de datos. Y lo testeamos de verdad: pruebas automatizadas con Jest y Vitest, incluido el rollback atómico —si algo falla a mitad de una operación, no quedan datos a medio guardar—.”
